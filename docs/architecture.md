# AKJ 웹 구조

ATELIER KJ의 웹은 세 덩어리로 나눈다. 공개 사이트와 사내 포털은 같은 저장소에 있지만 돌아가는 곳이 다르다.

| 덩어리 | 무엇 | 돌아가는 곳 | 폴더 |
|---|---|---|---|
| 공개 사이트 | 포트폴리오, 회사 소개 | 외부 정적 호스팅 (Cloudflare Pages) | `site/` |
| 사내 포털 | 프로젝트 업무, 설계 도구, 회사 운영 | 회사 NAS (Docker), VPN 안 | `portal/` |
| 외부 서비스 | 메일 서버, 음성인식·AI API, 전자서명 | 각 서비스 | — |

## 포털이 맡는 것과 데스크톱이 맡는 것

목표는 "회사 일이 포털 안에서 굴러가는 것" — 슬랙·노션·캘린더·메신저 역할을 포털 하나가 한다.
다만 CAD·라이노·일러스트 같은 저작 도구는 웹으로 대신하지 않는다.

| 포털 | 데스크톱 프로그램 |
|---|---|
| 프로젝트 허브, 메신저(프로젝트 채널), 캘린더, 회의록, 메일, 결재·근태·계약·인사 | 도면·모델링·그래픽 작업 (AutoCAD, Rhino, Illustrator, Photoshop) |
| 도면·모델 **보기·치수·마크업**, 파일 찾기 | 파일 **편집** |
| 파일 행의 "○○에서 열기" → 사내 연결 도우미(akj-open)가 NAS 경로로 데스크톱 프로그램을 연다 | 저장하면 NAS 폴더에 그대로 — 포털이 다시 읽는다 |

- 브라우저는 보안상 PC 프로그램을 직접 실행하지 못한다. 그래서 PC마다 작은 연결 도우미(사용자 지정 URL 처리기)를 설치하는 방식으로 간다. NAS 구축 후 만든다.
- 메신저는 포털의 일부로 만들되, 실시간 서버·휴대폰 알림까지 직접 만드는 비용이 크다. Mattermost 같은 사내 설치형 메신저를 NAS에 올리고 포털과 연동하는 안을 같이 비교한다.
- 포털 안에서 생긴 일(결재, 회의록 저장, 메일 도착, 일정 추가)은 그 프로젝트 채널에 자동 알림으로 남는다.

## 원칙

1. **NAS는 인터넷에 직접 열지 않는다.** 밖에서는 VPN으로만 들어온다.
2. **공개 사이트는 NAS에 올리지 않는다.** 회사 자료가 든 서버와 공개 서버를 섞지 않는다.
3. **계산은 코드, 판단은 AI.** 법규·면적·사업성 숫자는 코드가 내고 근거를 같이 남긴다 (AAD System과 같은 원칙).
4. **원본은 덮어쓰지 않는다.** 웹에서 고친 결과는 새 버전으로 저장하고, NAS 스냅샷으로 되돌릴 수 있게 둔다.
5. **고객 자료는 외부 변환·저장 서비스에 올리지 않는다.** 도면 변환은 사내에서 한다.
6. **민감정보는 마지막 단계에서, 꼭 필요한 것만.** 주민번호·급여·계좌는 암호화해 둔다. 급여·4대보험 계산은 세무 대행을 유지한다.
7. **키는 서버에만.** API 키와 비밀번호는 저장소에 커밋하지 않는다.

## 데이터 흐름

**파일·도면**
```
NAS 프로젝트 폴더 (.dwg / .3dm 원본)
  → 변환 (DWG → DXF, 3DM → 웹용 경량 파일)
  → 포털 뷰어 (WebGL)
  → 코멘트·마크업은 포털 DB에 따로 저장
```

**메일**
```
메일 서비스 ←IMAP→ 포털 → NAS 보관 (원본·첨부) → 프로젝트 코드별 분류
보관이 확인된 오래된 메일만 메일 서비스에서 정리한다
```

**회의록**
```
녹음 업로드 → 음성인식 API → AKJ 회의록 규칙으로 정리 → 프로젝트 폴더
```

## 기술

- 포털: Next.js 16 (App Router) + TypeScript + Tailwind — AAD System과 같은 스택
- 3DM: rhino3dm (라이노 개발사 공식 오픈소스)
- DWG: ODA File Converter 또는 LibreDWG로 DXF 변환 → three.js로 표시. 한글 SHX 글꼴은 일반 한글 글꼴로 대체
- 배포: `output: "standalone"` 빌드 → NAS Container Manager (Docker)
- 로그인: Next.js 16에서 `middleware`가 `proxy`로 바뀌었다. 인증은 `proxy`에서 처리할 예정

## 단계

전환 단계와 포털 기능 단계는 포털의 `/roadmap` 화면에 있다. 원본 데이터는 두 파일이다.

- `portal/src/lib/roadmap.ts` — 구글 → NAS 전환, 공개 사이트 배포
- `portal/src/lib/modules.ts` — 포털 모듈별 단계(1~3)와 상태

## 정할 것

- 메일·캘린더 서비스 — 다음 스마트워크(무료) / 네이버웍스 Standard / Exchange Online. 포털 연결에 IMAP이 꼭 필요하다
- 로그인 방식 — NAS 계정 연동 또는 포털 자체 계정
- 데이터 저장 — SQLite로 시작할지, Postgres로 갈지
- 저장소 공개 여부 — 지금은 공개 저장소다. 포털에 실제 업무 기능이 들어가기 전에 비공개로 바꾼다
